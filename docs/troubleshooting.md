# Диагностика и проблемы

## Главная причина падений в фоне

Не отсутствие wake-lock, а фирменный батарейный менеджер прошивки
(MIUI/EMUI/ColorOS/OneUI/...): живёт отдельно от AOSP Doze и убивает фон
без объяснений. Android не даёт стороннему приложению снять это ограничение
программно — только открыть нужный экран (`battery-settings`) и переключить
руками: «Без ограничений» / «Не оптимизировать». На части прошивок рядом
отдельная настройка «Автозапуск» / «Работа в фоне» — тоже включить.
То же сделать для Termux:Boot / Termux:API, если стоят отдельно.

## Памятка MIUI 12.5 (`miui-help`)

1. Настройки → Приложения → Все приложения → Termux → Батарея → Нет ограничений.
2. Настройки → Приложения → Разрешения → Автозапуск → включить Termux.
3. Недавние приложения → удержать Termux → значок замка.
4. Безопасность → Ускорение → Настройки → Закреплённые приложения → Termux.
5. Повторить пп. 1–2 для Termux:Boot и Termux:API.
6. Не скрывать постоянное уведомление Termux, не запускать «Очистку памяти».
7. В Termux: `tgws watchdog-on` и `tgws autostart-on`.

## Termux:API не отвечает

Симптомы: коды `124`, «не ответил за 6 с», не копируется буфер, не ставится
задача планировщика. Причина почти всегда одна: установлен пакет
`termux-api`, но не установлено приложение Termux:API из того же источника,
что и Termux (F-Droid). Проверяется пунктом `12) Диагностика`.

## Порт занят, tmux-сессии нет

Висящий процесс ядра без сессии. `start` сам находит это, прибивает
(`force-kill`: `TERM`, потом `KILL -9`) и стартует заново; если порт всё ещё
занят — значит, его держит другое приложение. После аварийного убийства
сервера tmux (SIGKILL от MIUI) скрипт чистит каталог сокета, но только если
`tmux ls` вообще не отвечает — живую сессию не трогает никогда.
Рассинхрон «сессия есть, процесса нет» (выход из Doze) показывает `status`.

## Лог пуст / нет ошибок

- `proxy.log` появляется после первого запуска; ротация — по `LOG_MAX_MB`/`LOG_BACKUPS`
  на стороне ядра. `clear-logs` трёт лог и ротированные копии.
- `boot.log` — только после срабатывания автозапуска; пуст = ещё ни разу не срабатывал.
- IP клиентов видны только при `VERBOSE=1` (п. 9 настроек), иначе `conns`
  покажет только живые сокеты/соседей по ARP.
- Последние ошибки: `stats`; живой хвост: `logs`.

## Диагностика (`doctor`)

Проверяет: бинарники (`git python tmux curl openssl pgrep nc`),
проект и ядро, venv (если включён), Python ≥ 3.8, импорт `cryptography`,
wake-lock, батарею (руками, п. 30), планировщик, `qrencode`, автозапуск,
secret (32 hex), tmux-сессию, порт, `~/storage`, ревизию git, интерфейсы.

## FAQ

- **Обновления?** `check-update` сравнивает `HEAD` с `REPO_BRANCH`
  (`git fetch origin --tags`), бейдж в меню. Локальные правки в проекте
  блокируют `update` — скрипт предупредит и предложит `reset --hard`.
- **Ссылка не работает с других устройств?** Нужен `BIND_MODE=lan` (п. 10)
  и правильный интерфейс (п. 11): для точки доступа обычно `ap0` (`192.168.x.1`).
  В `local` снаружи недоступен по определению.
- **Поменял Wi-Fi — старая ссылка?** `LAN_IP` из конфига используется, только
  если адрес реально есть на интерфейсах, иначе пересчитывается.
- **Тестовые ДЦ / PROXY protocol?** Только для отладки и для работы за
  nginx/haproxy соответственно; обычным клиентам не нужны.
- **Сокеты в `conns` пустые, а клиенты есть?** Android прячет таблицу —
  смотри раздел активности по логу/tmux-буферу ниже в том же выводе.
