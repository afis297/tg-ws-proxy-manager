# Автозапуск и watchdog

Три независимых механизма (можно комбинировать):

1. **Termux:Boot** — старт после перезагрузки телефона.
2. **Планировщик Android** — проверка примерно раз в 15 минут + после перезагрузки, без Termux:Boot.
3. **Watchdog + pane-died хук** — рестарт упавшего/зависшего процесса во время работы.

Состояние для меню хранится локально (файлы, не опрос API):
`~/.termux/boot/10-tg-ws-proxy.sh` → «Termux:Boot»,
`~/.local/state/tg-ws-proxy/job.enabled` → «планировщик».

## 1. Termux:Boot (`autostart-on/off/check`)

Нужно приложение Termux:Boot из F-Droid (версия из Google Play не подходит),
открытое один раз вручную, и выключенная оптимизация батареи для Termux и Termux:Boot.

Скрипт `~/.termux/boot/10-tg-ws-proxy.sh` (генерируется, права `700`)
работает в бедном окружении (без `PATH`/`HOME`), поэтому всё прописано явно:
берёт wake-lock, ждёт сеть (`BOOT_START_DELAY=15` с, до 3 попыток через
`BOOT_RETRY_DELAY=20` с), стартует прокси, пишет в `boot.log`.
Единый `TMUX_TMPDIR` для всех точек входа — иначе JobScheduler/boot-скрипт
и интерактивная сессия разъедутся по разным tmux-сокетам и поверх живого
прокси поднимется второй процесс.
Проверка без перезагрузки: `bash ~/.termux/boot/10-tg-ws-proxy.sh`,
пункт `autostart-check` показывает скрипт, приложение, задачу планировщика,
аптайм телефона и хвост `boot.log`.

## 2. Планировщик Android (`autostart-job-on/off`)

Без Termux:Boot. Нужны `pkg install termux-api` + приложение Termux:API.
Задача (`termux-job-scheduler`, job id `1443`, период `900005` мс — ровно
`900000` часть прошивок отбрасывает, `persisted`, `network any`)
раз в ~15 минут запускает `boot-job.sh`: если tmux-сессия жива — ничего не делает,
иначе поднимает прокси. Живой прокси повторно не трогается.
Все вызовы Termux:API идут через таймаут 6 с: без установленного приложения
они висят вечно и утянули бы за собой всё меню (код `124` = нет ответа —
значит, нужен именно APK из F-Droid, пакета `termux-api` недостаточно).

## 3. Watchdog и pane-died хук (`watchdog-on/off/status`)

- **pane-died хук**: мгновенный рестарт по факту смерти панели tmux.
  Флаг `manual_stop` отличает плановую остановку (`stop`/`restart`) —
  хук его съедает и молчит. Rate-limit 10 с против цикла падений.
- **Watchdog** (`tgwsproxydog`, проверка каждые `WATCHDOG_INTERVAL`):
  страховка от зависшего, но не упавшего процесса (TCP-опрос порта).
  После 5 подряд неудачных рестартов — экспоненциальный бэкофф (до ×10
  интервалов) и одно уведомление через `termux-notification`, чтобы сломанный
  конфиг не выжирал батарею вечным циклом.
- `RESTART_EVERY_H` — плановый перезапуск каждые N часов (нужен watchdog).

## Wake-lock

При старте берётся `termux-wake-lock` (если `WAKE_LOCK=1`), при остановке —
`termux-wake-unlock`. Без него Android усыпит прокси после блокировки экрана.
Но чаще прокси убивает не сон, а фирменный батарейный менеджер прошивки —
см. [диагностику](troubleshooting.md): программно это не отключается,
только руками в настройках.
